# Gabarits de README par catégorie

Règle commune : un README répond en moins de 30 secondes à quatre questions — **c'est quoi ? qu'a fait Hamdy ? comment le vérifier ? quelles limites ?** Toute affirmation absolue, métrique volatile, niveau de sécurité ou résultat est reliée à une source, un test, une date, un commit — ou reformulée. Les preuves passent avant les adjectifs.

| Catégorie | Plan |
|---|---|
| **Production / flagship** | Problème → rôle de Hamdy → architecture → preuve (démo, CI, tests, exécutions) → lancer en local → limites |
| **Support / DevOps** | Problème → ce que fait le mécanisme → architecture → preuve d'usage → versionnage et compatibilité → limites |
| **Académique** | Statut + cadre (cursus, date) → contexte et équipe → **contribution personnelle** → ce qui a été réellement fait **vs** seulement conçu → preuve → limites |
| **Lab** | Statut → hypothèse → garde-fous de sécurité → tests → résultat → limites |
| **Fork tiers** | Upstream → delta personnel (ou « aucun ») → raison de l'usage |
| **Archive** | Statut + date → pourquoi archivé → remplacement → précautions si réutilisé |
| **Privé** | Statut privé + pourquoi → rôle → ce qui est volontairement hors du document |
